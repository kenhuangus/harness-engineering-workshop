The Thesis · Chapter 1

The harness is the control plane. Not the prompt.

A long-horizon agent reads new context, delegates to new agents, resumes tomorrow, and changes memory. A prompt cannot check those transitions. A harness can.

What the harness mediates

What agents may know, remember, decide, delegate, execute, observe, resume, and improve.

How you judge it

Every control leaves evidence: a decision, a checkpoint, a ledger entry, a trace envelope, a hash.

How you improve it

Hill climbing with mandatory gates. A step counts only when the score rises and identity, intent, tool, runtime, and evidence gates stay in place.

Today you run that argument as code. No cloud account. No paid model API. No live secrets. Python 3.11+ and the standard library only.

Identity · Intent · Tools

Context · Memory

Runtime · Evidence · Governance

Checkpoints and pause. A control-evidence matrix. Hill-climb rules that keep mandatory gates.

Block A · Chapter 2 · The Reversibility Test

Autonomy is a ladder, not a switch.

Chapter 2 sorts actions by reversibility: read-only, reversible write, costly reversible, irreversible. A read is not a customer email. A customer email is not a deleted record. Each level gets its own control.

Automatic

Low-risk work runs. Capability budgets cap the spend per run and across runs.

Supervised

Externally visible work queues for a human. The approval packet binds the decision to the exact payload.

Blocked

Some controls are non-waivable. No reviewer may approve secret access by waiver.

Book section 2.13, the Autonomy Review Board: mission, action catalog, approval workflow, budgets, long-horizon controls, evidence. Use it in the capstone to judge your own extension.

Block B · 0:45–1:25 · Chapters 3–4

Who is acting, and for what purpose?

Chapter 3 replaces shared tokens with per-agent and per-task identity: short-lived, audience-bound, revocable credentials, with a delegation chain that names the parent. Chapter 4 binds the run to an intent contract: tools, data, risk, evidence, and when reauthorization is required.

Identity envelope

Agent, task, credential, delegation, audience, resource. Verification needs both the allow and the deny: the same credential must work for ticketing and fail for the repo.

Intent contract

“Help with billing” is not an all-access pass. Drift is detected when the run reads new context, resumes, or follows a subgoal outside the approved purpose. Objective hijacking is a drift case, not a new category.

Book sections 3.3–3.10 and 4.2–4.7. Long-horizon point: credentials expire, pause, resume, and renew. Intent expires too, and resume must revalidate it.

Block B · Chapter 5 · Trust Tiers

Context is a security boundary.

Chapter 5 asks which classified, provenance-bound, freshness-checked context is safe to release into this step of this run. Relevance is not authority. A public issue comment can be relevant and still carry instructions.

Trust tiers

Release only fresh, trusted context. Provenance must be able to testify where each item came from.

Quarantine

External material is isolated, not deleted. Quarantine evidence is preserved for review.

Lethal trifecta

Private data + tool access + external sink, in one step, is blocked. Each part alone looks harmless.

Book sections 5.4–5.9: trust tiers, provenance, isolation and quarantine, poisoning in RAG, tools, and subagents, profile-based configuration, compaction and refresh.

Block C · 1:25–2:05 · Chapters 6–7

Memory changes future behavior. Traces prove it.

Chapter 6 gates memory writes: candidate state becomes authorized memory only through a firewall, a ledger, and a handoff path. Chapter 7 turns traces into evidence: decision traces, evidence envelopes, artifact hashes, and evals as executable risk controls.

Memory firewall + ledger

Writes are gated by source trust. Promotion goes through handoff. Tenants are isolated. Records expire by TTL. Poisoned memory is tombstoned on rollback, not silently edited.

Evidence traces

Redacted spans, sealed evidence, replay bundles. A benchmark regression is proof, not an opinion. Recursive self-improvement stops at a governance boundary.

Book sections 6.3–6.7 and 7.2–7.9. Long-horizon point: memory and traces outlive the run that created them. That is why both need a control plane.

Block C · Chapter 8 · After the Run Starts

Steer a run that is already in motion.

Chapters 1–7 shape a run before it starts. Chapter 8 covers the rest: a ticket gains a hostile comment mid-run, a tool is reclassified, a new policy lands while the agent is halfway through a task. The harness must intervene without destroying forensic evidence.

Observe → warn → pause

Intervention is graded. Not every signal is a kill.

Block → kill → contain

Unsafe output is blocked. A retrying subtask is killed. A compromised part is contained.

Recover → replay → compensate

Resume from a checkpoint. Replay the evidence. Roll back with compensation. Bounded policy overlays expire.

Book sections 8.1–8.5: approvals to interrupts, runtime policy injection, circuit breakers and kill switches, containment, checkpoints, replay, fork, and rollback.

Block D · 2:05–2:45 · Chapters 9–10

One safe agent is not a safe fleet.

Chapter 9 admits work before executing it: tenant bulkheads, fair admission, back-pressure, idempotent retries, compromised-worker containment, capacity governance. Chapter 10 makes data governance runtime: classification is a fact carried through tools, memory, traces, and output — not a note in a policy document.

Fleet

Work is admitted, queued, and leased. Back-pressure is a signal. Retries repeat only idempotent actions. A compromised worker is quarantined, not trusted to self-report.

Data governance

Labels persist across resume. Egress and residency are checked at runtime. Secret leakage escalates. Erasure is proved across memory and trace evidence.

Book sections 9.2–9.8 and 10.3–10.10. Long-horizon point: scale and data handling are where a demo that looked safe becomes a system that fails quietly.

Capstone · 2:25–2:45 · 20 minutes

Extend one lab with one realistic failure.

Pick one. Implement it in the chapter scenario, run it, and show the new decision in the JSON. The control must preserve useful agency while the run stays bounded, justified, traced, interruptible, and recoverable.

1 · Stale approval

An approval granted before a pause is used after resume. Require reauthorization.

2 · Borrowed credential

A subagent uses its parent credential. Deny it; issue a task-scoped credential instead.

3 · Poisoned memory

An untrusted source promotes a durable rule. Gate the write; tombstone the record.

4 · Thin trace

A trace omits an artifact hash. Fail the eval until the envelope is complete.

5 · Unsafe retry

A retry repeats a non-idempotent action. Make the retry idempotent or block it.

6 · Lost label

A data label disappears before egress. Block egress until the label is restored.

Demo format, 2 minutes per team: the failure, the control, the decision in the JSON, and the artifact an auditor would read.
