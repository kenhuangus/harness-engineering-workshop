Lab Guide

Source: kenhuangus/Harness-Engineering-Design-Patterns, the companion repo for Harness Engineering: Design Patterns for Securing Long-Horizon Multi-Agent AI Systems (Packt). Book table of contents: Google Doc. No cloud account, no paid model API, no live secrets. Python 3.11+ and the standard library only.

Method for every lab: run first, read the JSON decisions without looking at the implementation, identify the unsafe path and the artifact an auditor would ask for, then inspect scenario.py to find the control that changed the outcome.

Setup

git clone https://github.com/kenhuangus/Harness-Engineering-Design-Patterns.git
cd Harness-Engineering-Design-Patterns
python3 -m venv .venv && source .venv/bin/activate
python -m pip install -e .
python -m harnesslab.cli list
python -m harnesslab.cli run all
python -m unittest discover -s tests

Expected: list shows ch01–ch10. run all prints PASS for all 10. unittest prints OK, 5 tests. Troubleshooting: on Debian/Ubuntu, system Python refuses pip install outside a venv (PEP 668) — use the venv above. Python must be 3.11 or later (python3 --version).

Lab A1 — ch01: Harness as the Control Plane

Scenario: shared-deploy-swarm — planner, researcher, coder, deployer share one broad credential and deploy with no checkpoint. Find in the JSON: the safe internal-repo patch (allowed); five blocked or escalated paths (poisoned memory write, vault read, deploy attempt, privileged operation, unapproved egress); the quarantined external comment (injection markers + lethal-trifecta pattern); the checkpoint before deployment; the hill-climb path 0.24 → 0.96. Book: sections 1.1–1.12.

Lab A2 — ch02: Graduated Autonomy

Find: reversible patch allowed; customer communication queued, not sent; budget-exhaustion denial; blocked irreversible customer-data action; rejected secret-access waiver; renewed lease after expiry; rollback hook after the reversible write. Book: sections 2.3–2.5 and 2.13 (Autonomy Review Board).

Lab B1 — ch03 + ch04: Identity and Intent

ch03: four agent identities, separate task identities, audience mismatch (ticketing credential fails on the repo), expired credential denied, delegation chain agent-planner → agent-patcher, revocation denied on re-use. ch04: the billing remediation agent stays inside its purpose; tool scope, data scope, risk, evidence, stale goals, and resume state are each checked. Book: sections 3.3–3.10, 3.13 (walkthrough), and 4.2–4.7.

Lab B2 — ch05: Context

Find: high-assurance context profile selected; only fresh trusted context released; external item quarantined with findings; lethal-trifecta egress blocked; checkpoint with quarantine evidence persisted. Book: sections 5.4–5.9 and 5.12.

Lab C1 — ch06 + ch07: Memory and Observability

ch06: gated write, handoff promotion, ledger entry, tenant isolation, TTL expiry, tombstone on rollback. ch07: risky action observed with redacted traces, evidence sealed with artifact hashes, replay bundle built, benchmark regression detected, hill-climbing eval loop governed. Book: sections 6.3–6.7 and 7.2–7.9, 7.13.

Lab C2 — ch08: Runtime Steering

Find: warning on hostile context, pause, blocked unsafe output, killed retrying subtask, recovery from checkpoint, replay of evidence, safe rollback with compensation, bounded policy overlay expiring. Book: sections 8.1–8.5.

Lab D — ch09 + ch10: Fleet and Data Governance

ch09: tenant bulkheads, queues, quotas, rate-limit back-pressure, idempotent retry, quarantined compromised worker, capacity epoch. ch10: labeled data through approved profiles, unsafe egress blocked, residency drift blocked, secret leakage escalated, labels persisted across resume, erasure proved across memory and trace evidence. Book: sections 9.2–9.8, 9.11, and 10.3–10.10.

Capstone — extend one lab

Pick one failure, implement it in the chapter scenario, run it, and show the new decision in the JSON:

  1. Stale approval used after resume — require reauthorization.
  2. Subagent uses its parent credential — deny it; issue a task-scoped credential.
  3. Untrusted source promotes a durable memory rule — gate the write; tombstone the record.
  4. Trace omits an artifact hash — fail the eval until the envelope is complete.
  5. Retry repeats a non-idempotent action — make it idempotent or block it.
  6. Data label disappears before egress — block egress until the label is restored.

Demo format per team: the failure, the control, the decision in the JSON, and the artifact an auditor would read. Judge it with the Autonomy Review Board (Chapter 2, section 2.13): mission, action catalog, approval workflow, budgets, long-horizon controls, evidence.

After the workshop

Pick one agent workflow you own. Write its intent contract — tools, data, risk ceiling, evidence, expiry — in five lines. Run the matching HarnessLab chapter against it. Bring the gaps to an Autonomy Review Board.
